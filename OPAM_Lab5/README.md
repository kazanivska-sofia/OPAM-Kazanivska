## Завдання 5. Обґрунтування вибору структур даних

### 1. Перевірка збалансованості дужок (Стек)
У цій задачі використовується стек, оскільки закривальна дужка завжди має відповідати **останній** відкритій дужці (принцип LIFO — Last In, First Out). 
Якщо взяти чергу, порушиться порядок парності (найперша відкрита дужка перевірятиметься з першою закривальною, що повністю зламає вкладеність на зразок `([()])`). Список тут надлишковий, бо доступ потрібен лише до останнього збереженого елемента.

### 2. Обчислення у зворотному польському записі (Стек)
Операції обчислюються над останніми двома введеними операндами (LIFO). Стек дозволяє зберігати проміжні результати та діставати їх у зворотному порядку для виконання бінарних операцій. 
Використання черги призведе до того, що операція застосовуватиметься до найстаріших чисел, що викривить математичний порядок обчислень.

### 3. Модель обслуговування (Черга)
Модель обслуговування реалізує принцип справедливості FIFO (First In, First Out): заявка, яка надійшла першою, має бути обслуговувана першою. 
Якщо замість черги взяти стек, виникне «голодування» даних (заявка, що прийшла першою, обслугується найостаннішою).

### Чому Queue.Dequeue() дешевша за List.RemoveAt(0)?
Метод `List.RemoveAt(0)` має часову складність $O(N)$, оскільки після видалення першого елемента всі інші $N-1$ елементів масиву зсуваються на одну позицію вліво. 
У той же час `Queue<T>` реалізована на основі кільцевого буфера (Circular Buffer): метод `Dequeue()` лише збільшує вказівник на початок черги без реального фізичного переміщення елементів у пам'яті, що забезпечує часову складність $O(1)$.
